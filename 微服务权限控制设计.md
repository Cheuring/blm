# 微服务权限控制设计文档

## 1. 权限架构概述

本微服务架构采用基于角色的访问控制(RBAC)，通过JWT令牌传递用户身份和角色信息，结合AOP切面实现自动权限校验。

### 1.1 权限层级
```
SUPER_ADMIN (超级管理员)
├── 系统配置管理
├── 管理员账户管理  
├── 用户角色分配
├── 数据导出/日志查看
└── 所有ADMIN权限

ADMIN (管理员)
├── 平台统计查看
├── 用户封禁管理
├── 商家/骑手审核
└── 基础管理功能

MERCHANT (商家)
├── 店铺信息管理
├── 商品管理
├── 订单处理
├── 营销活动
└── 财务统计

RIDER (骑手)
├── 接单/送单
├── 位置更新
├── 配送状态管理
└── 收入查看

USER (用户)
├── 个人信息管理
├── 下单/支付
├── 地址管理
└── 订单查询
```

## 2. 权限实现机制

### 2.1 JWT令牌结构
```json
{
  "sub": "12345",
  "roles": "USER,MERCHANT",
  "iat": 1640995200,
  "exp": 1641001200
}
```

### 2.2 API网关权限过滤
```java
// AuthFilter 核心逻辑
public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
    // 1. 提取JWT令牌
    String token = extractToken(request);
    
    // 2. 验证令牌有效性
    if (!jwtUtil.validateToken(token)) {
        return unauthorized(exchange);
    }
    
    // 3. 解析用户信息和角色
    String userId = jwtUtil.getUserIdFromToken(token);
    List<String> roles = jwtUtil.getRolesFromToken(token);
    
    // 4. 添加请求头传递给下游服务
    ServerHttpRequest modifiedRequest = request.mutate()
        .header("X-User-Id", userId)
        .header("X-User-Roles", String.join(",", roles))
        .build();
    
    return chain.filter(exchange.mutate().request(modifiedRequest).build());
}
```

### 2.3 权限注解
```java
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireRole {
    String[] value();                    // 需要的角色列表
    String logic() default "OR";         // 逻辑关系：OR/AND
    String message() default "权限不足";  // 错误信息
}
```

### 2.4 AOP权限切面
```java
@Around("@annotation(requireRole)")
public Object checkPermission(ProceedingJoinPoint joinPoint, RequireRole requireRole) {
    // 1. 从请求头获取用户角色
    HttpServletRequest request = ((ServletRequestAttributes) 
        RequestContextHolder.currentRequestAttributes()).getRequest();
    String userRoles = request.getHeader("X-User-Roles");
    
    // 2. 校验权限
    if (!hasPermission(userRoles, requireRole)) {
        throw new PermissionDeniedException(requireRole.message());
    }
    
    // 3. 执行目标方法
    return joinPoint.proceed();
}
```

## 3. 各服务权限控制示例

### 3.1 用户服务 (user-service)
```java

    public Result<Void> register(@RequestBody UserRegisterDTO dto) {}

    @GetMapping("/profile")
    @RequireRole({"USER", "MERCHANT", "RIDER", "ADMIN"})
```

## 4. 权限校验流程

### 4.1 完整权限校验流程
```
1. 客户端发送请求 (携带JWT Token)
   ↓
2. API网关 AuthFilter
   ├── 验证Token有效性
   ├── 解析用户ID和角色
   ├── 添加请求头传递信息
   └── 路由到目标服务
   ↓
3. 目标服务 AuthorizationAspect
   ├── 拦截@RequireRole注解的方法
   ├── 从请求头读取用户角色
   ├── 校验是否有所需权限
   └── 决定是否允许执行
   ↓
4. 业务方法执行
   └── 返回结果给客户端
```

### 4.2 权限校验逻辑
```java
private boolean hasPermission(String userRoles, RequireRole requireRole) {
    if (userRoles == null || userRoles.isEmpty()) {
        return false;
    }
    
    List<String> roles = Arrays.asList(userRoles.split(","));
    List<String> requiredRoles = Arrays.asList(requireRole.value());
    
    if ("AND".equals(requireRole.logic())) {
        // 需要同时拥有所有角色
        return roles.containsAll(requiredRoles);
    } else {
        // 拥有任一角色即可 (默认OR逻辑)
        return requiredRoles.stream().anyMatch(roles::contains);
    }
}
```

## 5. 角色管理和分配

### 5.1 用户多角色支持
用户可以同时拥有多个角色，如：
- 用户+商家：既可以下单，也可以开店
- 用户+骑手：既可以点餐，也可以送餐
- 管理员+商家：管理员可以开设示范店铺

### 5.2 角色分配接口
```java

    @PathVariable Long userId,
    @RequestParam String roles,      // "MERCHANT,RIDER"

    return Result.success();
}
```

### 5.3 角色验证策略
```java
// 业务层面的角色验证
public class RoleValidationService {
    
    // 验证用户是否可以申请商家
    public boolean canApplyMerchant(User user) {
        return user.hasRole("USER") && !user.hasRole("MERCHANT");
    }
    
    // 验证商家是否可以处理订单
    public boolean canProcessOrder(User merchant, Order order) {
        return merchant.hasRole("MERCHANT") && 
               order.getStoreId().equals(merchant.getStoreId());
    }
    
    // 验证骑手是否可以接单
    public boolean canAcceptOrder(User rider, Order order) {
        return rider.hasRole("RIDER") && 
               rider.isOnline() && 
               order.getStatus().equals("WAITING_DELIVERY");
    }
}
```

## 6. 安全注意事项

### 6.1 令牌安全
- JWT令牌包含敏感信息，使用HTTPS传输
- 设置合理的过期时间（Access Token 2小时，Refresh Token 7天）
- 支持令牌撤销和黑名单机制

### 6.2 权限提升防护
- 严格验证角色分配操作的权限
- 记录所有权限变更的审计日志
- 防止用户通过API直接修改自己的角色

### 6.3 异常处理
```java
@ControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(PermissionDeniedException.class)
    public Result<Void> handlePermissionDenied(PermissionDeniedException e) {
        log.warn("权限不足: {}", e.getMessage());
        return Result.error(ResultCode.PERMISSION_DENIED, e.getMessage());
    }
    
    @ExceptionHandler(TokenExpiredException.class)
    public Result<Void> handleTokenExpired(TokenExpiredException e) {
        return Result.error(ResultCode.TOKEN_EXPIRED, "令牌已过期，请重新登录");
    }
}
```

## 7. 测试和监控

### 7.1 权限测试
每个API接口都应该测试：
1. 无权限访问（401）
2. 权限不足访问（403）
3. 正确权限访问（200）
4. 边界权限访问（如角色组合）

### 7.2 权限监控
- 监控异常权限访问尝试
- 统计各角色的API调用频率
- 记录权限变更操作日志
- 定期审查用户权限分配

这个权限控制设计确保了微服务架构中的安全性，同时保持了良好的扩展性和维护性。
